> 这两周杜老师做技术选型时接连被两件事扎到：MinIO 在 5 月悄悄砍掉了社区版的 Web Console，11 万行代码删除；Mattermost v11 给免费版加了"消息历史最多 1 万条"的限制——旧消息还躺在数据库里，但 UI 看不见了。摆在一起看，**"屠龙的少年长出了龙鳞"** 这事好像不再是个比喻。写篇文章，把这两年"开源变收费"的剧本翻出来聊聊。

<!-- more -->

## 两件小事

**第一件：MinIO 砍 WebUI。** 2025 年 5 月，MinIO 悄悄合并了一个 PR，**把社区版的 Web Console 砍掉了**。11 万行代码删除，只剩一个能看能下载的对象浏览器。你想改个 IAM 策略、看一眼监控指标、配个桶复制？对不起，请升级到 MinIO AIStor Enterprise Edition，**起价 9.6 万美元一年**。

**第二件：Mattermost 限 1 万消息。** 2025 年 12 月发布的 v11 给免费版加了一个神奇的限制——**消息历史最多 1 万条**。超出的旧消息依然躺在你自己的 PostgreSQL 数据库里，但 UI 看不见、搜不到。一所学校 2000 多用户、47 万条历史消息，瞬间被"折叠"。Mattermost 的官方说法是"防止过度部署"，社区里更准确的描述是 **"bait-and-switch"**（先诱后宰）。

两件事摆一起看，忽然就明白了一件事：**"开源的尽头是收费"不是预言，是 2025 年起所有基础设施软件正在发生的现实**。

## MinIO 十年堕落史

{% image https://cdn.dusays.com/2026/09/888-1.png  ratio:1918/866 %}

*MinIO 时间线：从 Apache 2.0 起步，到 2026-04 仓库归档*

MinIO 的故事值得展开讲讲，因为它把"开源变收费"的剧本演得最完整：

| 时间 | 事件 | 性质 |
|---|---|---|
| **2014** | 公司成立，Apache 2.0 许可证 | 屠龙少年，理想主义 |
| **2019-2021** | 许可证从 Apache 2.0 → AGPLv3 | "防止云厂商白嫖"——但已经埋下商业化伏笔 |
| **2022-2023** | 起诉 Nutanix、Weka | 法律武器化 |
| **2025-05** | 社区版砍掉 Web Console（11 万行删除） | 表面看"防白嫖"，实际是逼付费 |
| **2025-09** | 停止社区版 Docker 镜像分发 | 让"自建"也得花时间成本 |
| **2025-12** | 官方宣布 GitHub 仓库进入"维护模式" | 名存实亡 |
| **2026-04** | 仓库归档 | 正式死亡 |

更扎心的是它"留了条活路"的姿态——CEO Anand Babu Periasamy 在采访里说：

> "开发者真正需要的是 API，不是 Web UI。"

听听这话：你都要花 9.6 万美元买的"管理界面"，他告诉你"你不需要"。但任何用过 MinIO 的人都懂——CLI 配 IAM、Replication、监控，是真的反人类。

社区的反应也很真实：

> *"Open source users aren't confused. They're insulted. Know the difference between community and capture?"*（开源用户不是困惑，是被侮辱了。"社区"和"俘获"的区别，懂吗？）

MinIO 还没有改协议——它依然 AGPLv3，依然"开源"。但 GitHub 仓库归档那一刻起，"License 是开源"和"项目是开源"，**已经是两回事**了。

## Mattermost 的"温柔一刀"

{% image https://cdn.dusays.com/2026/09/888-2.png  ratio:1918/866 %}

*配图：聊天 UI 顶部红色告警进度条，旧消息逐渐灰化坠入虚空——"消息历史已达到上限"*

Mattermost 是"软切"，MinIO 是"硬切"。但这两种切法背后，是同一套剧本。

Mattermost v11 的"免费版 Entry"（前身 E0）加了一堆"看起来很美"的限制：

- 📜 **消息历史 10,000 条**（旧消息还在 DB，但 UI 不可见）
- 📨 **推送通知 10,000 条/月**
- 📋 **看板卡片 1,000 个**
- 🎬 **剧本运行 5 次/月**
- 🎙️ **1:1 音频通话 40 分钟**
- 🤖 **AI 助手 250 次/月**

加上 Team Edition（真·MIT 协议版）的限制：**用户上限 250，GitLab SSO 没了**。

懂了吗？这套组合拳的核心是——

> **先用"高级功能免费"把用户圈进来，再等用户用顺手、用出依赖，最后用"消息历史上限"逼你付费。**

byteiota 那篇文章里有个精准的比喻：

> *"Messages remain in the database but become inaccessible through the UI. It's digital hostage-taking."*（消息还在数据库，但 UI 看不到。这是数字人质劫持。）

而且 Mattermost 没有给过渡期：**v11 一发布，所有现存实例都立刻生效**。一家用 Mattermost 三年的学校管理员在 GitHub 上问：

> *"How can we trust Mattermost from now on?"*（从今以后我们还能信 Mattermost 吗？）

这问题问得真好。

## 这不是孤例

把 MinIO、Mattermost 放进时间线看，会发现这早已是一股潮流：

| 年份 | 项目 | 发生了什么 |
|---|---|---|
| **2018** | MongoDB | AGPL → SSPL |
| **2021** | Elastic | Apache → SSPL（社区后来 fork 出 OpenSearch） |
| **2023** | HashiCorp Terraform | MPL → BSL（社区 fork 出 OpenTofu） |
| **2024** | Redis | BSD → SSPL + RSAL（社区 fork 出 Valkey；2025-05 部分回归，新增 AGPLv3 选项） |
| **2024** | CockroachDB | 直接取消免费 Core 版 |
| **2025-05** | MinIO | 砍 WebUI（保留 AGPLv3） |
| **2025-12** | Mattermost | 10,000 消息上限（保留 MIT，但限制功能） |

10 年间，6 个明星项目、5 种"软硬兼施"的手法，**结果都是同一个**：免费版越来越难用，付费墙越来越高。

**背后是同一套商业逻辑**：

> 投资人要回报 → 公司不能永远靠"开源精神"养活 → 限制免费版、倒逼付费 → 社区骂声一片但已离不开 → 收费闭环跑通。

## 为什么受伤的总是我们

认真想一下，**为什么"屠龙少年变恶龙"的剧本总是成立**？

三个必要条件同时满足，结局就注定：

1. **单一公司控制项目**（不是基金会、不是广泛社区）
2. **云厂商白嫖**（AWS、Azure 拿开源赚钱但不贡献代码）
3. **投资人要求回报**（烧了 VC 的钱总要吐出来）

三个条件里只要**少一个**，情况就不同：

- Apache、CNCF 旗下的项目（Kafka、Spark、Kubernetes）——背后是基金会，董事会多公司，没人能"绑架"项目
- Linux 内核、Python、PostgreSQL——无单一雇主控制，靠捐赠 + 多家公司雇佣贡献者
- 真正"屠龙者"和"恶龙"身份长期分离的项目——更不容易翻车

**这就是为什么我们以后挑基础设施，要先看它背后的"治理结构"，再看技术**。

## 我们该警惕什么？怎么做？

### 四个危险信号

看到这些，赶紧想退路：

1. **License 突然变更**（AGPLv3、SSPL、BSL 都是"危险牌"）
2. **免费版功能悄悄缩水**（不加新功能是常态；删老功能是警报）
3. **Docker 镜像停止分发**（"你得自己编译"等于"我们不想伺候免费用户"）
4. **公司被收购 / 融资异常**（新东家可能一上任就加速商业化）

### 选型的五条原则

1. **看治理，不看技术**——优先 Apache / CNCF / Linux Foundation 旗下项目
2. **看母公司，不看项目**——单一公司主导的明星项目都有"被收编"风险
3. **看 fork 活跃度**——Elastic 有 OpenSearch、Terraform 有 OpenTofu、Redis 有 Valkey，这是项目"被社区接管"能力的体现
4. **数据不外置**——任何"功能限制"如果影响你能看见自己服务器上的数据（比如 Mattermost 的消息限制），都是红旗
5. **关键路径双备**——别把生产环境的命脉单押给一家商业公司控制的项目

### MinIO / Mattermost 现在怎么选

**MinIO 的替代**：

- **Ceph**（重，老牌，复杂）
- **Garage**（轻量，新兴，Rust 写）
- **SeaweedFS**（速度快，专注海量小文件）
- **RustFS**（国产，对标 MinIO 刚起步）

**Mattermost 的替代**：

- **Matrix**（端到端加密，联邦架构，法国政府都在用）
- **Rocket.Chat**（Slack-like，定制能力强）
- **Zulip**（主题分流的邮件式讨论，开发组心头好）
- 或者直接退回 Mattermost Team Edition（虽然功能少，但 MIT 协议保底）

## 开源精神从未消失，只是换了地方

写到这里必须说一句：**开源不是死了，只是回到了它该在的地方**。

那些真正的"基础设施开源"——Linux、Kubernetes、PostgreSQL、Redis（社区版 AGPLv3）、Valkey、OpenSearch、OpenTofu——活得很好。它们有的被资本恶心过，但社区顶住了、有 fork、有基金会保护、有真正的自由。

反而是那些"曾经开源，现在想收费"的明星项目，正在被市场教训：

- Elastic 被 OpenSearch 抢市场份额
- HashiCorp 被 OpenTofu 抢基础设施客户
- Redis 不得不回归 AGPLv3
- MinIO 把名字搞臭了，仓库归档了

**所以这句话送给所有还在认真做开源的公司**：

> *你可以从开源出发，走向商业。但别走得太远——你走多远，社区的耐心就消失多远。等你回头，发现 Valkey 已经站在你曾经的位置了。*

至于我们用户：**保持清醒、多备一手、把数据握在自己手里**，就够了。
